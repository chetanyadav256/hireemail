## Phase 2 delivery boundary

Implemented tests cover deterministic classification, missing optional values, invalid/empty rows, formulas, real XLSX/XLS decoding, malformed/spoofed/oversized files, cross-owner access, CSRF, version conflicts, transactional concurrent duplicate prevention, idempotent save, search/pagination and expiry. Replica-set integration verifies XLSX worksheet selection, preview and persisted commit. Desktop/mobile browser coverage checks manual mapping, preview-before-save, mapping invalidation, selection, editing, soft deletion/restoration, history and mobile overflow. A gated live browser-to-API run verifies registration/login, CSV preview/commit/replay, persisted contacts, pagination/search/filter/edit, cross-user denial, restoration, logout and protected-route redirection. Current local results: `npm run check` passed (60 tests across 9 files plus lint/build), `npm run test:e2e` passed 14 tests with the two gated live project entries skipped, and the separate live API test passed. These checks use an isolated local test replica set and synthetic data; no database-dependent contact behavior is represented by an in-memory production fallback.

Before public deployment, verify the configured Atlas/replica-set topology and migrations, physical TTL cleanup, proxy/body timeouts, parser container/egress policy, bounded-load/failover behavior, privacy retention and backups. No automatic progression to resumes, AI generation or sending is authorized by this milestone.

## Test strategy

- Unit tests: contact normalization, row reasons, grounding validation, state transitions, snapshot hashing, limits and error classification.
- Current integration tests: API validation/auth, real replica-set transactions/indexes, parser boundaries, ownership, import concurrency/idempotency and persistence. Future integration tests: storage boundaries, OAuth callbacks, operation recovery and concurrent dispatch. Provider adapters remain fake.
- Current browser tests: desktop/mobile auth and contact import/management with mocked HTTP responses, plus an opt-in desktop live-API/test-database smoke test. Future browser tests: campaign review and approved fake send, rejected-row correction/reimport, reconnect and error recovery, mobile layouts, keyboard access and visible focus.
- Failure injection: crash before dispatch, after dispatch starts, and after provider success but before database acknowledgement; stale worker resume; revoked grant; missing attachment; duplicate idempotency keys; quota races.

Use Vitest, Supertest and Playwright as the planned test tools; choose and pin supported versions during scaffolding. Keep fixtures synthetic and representative. Avoid tests that merely mirror implementation details.

## Release gates and deferred decisions

Real sending stays disabled until milestones 1-12 pass. OAuth connection development may use test accounts earlier; it does not authorize outreach. A release must have reviewed retention/privacy terms, appropriate Google consent verification, operational ownership, provider spending limits, and a tested emergency send-disable control.

Before the affected milestone, select the LLM provider/model and its data-handling settings, object-storage/hosting region, transactional authentication-mail provider, and maintained upload/parser packages. Select dependency versions using current primary documentation and security review. These decisions do not block planning.

Deferred product scope: OCR, macro workbooks (legacy BIFF8 `.xls` is now explicitly supported), scheduled follow-ups, multiple Gmail identities per user, inbox/reply/bounce synchronization, open tracking, teams, billing, scraping, and automatic job matching. PostgreSQL, microservices, and alternate mail providers are not required for this plan.
